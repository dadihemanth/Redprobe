     Table of Contents (sections)

     1. Architecture Overview — RT vs Target vs Evaluator triangle; data flow diagram (ASCII or SVG inline); session lifecycle state
     machine
     2. The Red Team LLM (RT) — what RT is, why it's separate from Target, what "Switch RT to permissive provider" means and why
     (restrictive providers refuse adversarial system prompts), recommended providers for RT (HuggingFace, Mistral, local Ollama), which
     providers to avoid as RT (Azure Content Filter, Claude strict guardrails)
     3. Session Lifecycle — configuration → connection test → pre-launch estimate → attack loop → evaluation → report; state transitions
     in S; IndexedDB persistence; session entry schema fields
     4. Phase Schedule System — DEFAULT_PHASE_SCHEDULE (ESTABLISH 0–25% / INTRODUCE 25–55% / ESCALATE 55–75% / DIRECT 75–100%);
     phaseForTurn(schedule, t, turns) formula; per-phase system prompt construction; custom phase editor in custom technique builder
     5. Intent Generation Engine — INTENT_TEMPLATES[category] stealth-framed seeds; domain pack overlays (15 verticals); generateIntent()
     flow; anchor_ask pattern (deliverable-verb operational artifact); academic framing wrapper
     6. Jailbreak Payload Injection — JAILBREAK_PAYLOADS; per-category payload stats (payloadStats); 55%/30% probability gates;
     injectJailbreak() call site; how payloads are embedded into the RT-generated prompt
     7. Mutation & Breeder System — mutateBreakPrompt() (55% chance on any prior winning prompt); intent breeder (55% of remainder — reuse
      prior successful intent); failuresArchive refusal fingerprinting; how mutation prompts are passed back to RT LLM
     8. Auto-Tune System (4 Tracks) — detailed breakdown:
       - Track A: lessonsArchive — per-techId AI-generated lessons; how lesson is extracted post-batch; how it's injected into RT system
     prompt next session
       - Track B: statsMatrix — key format ${techId}||${catId}||${tgtKey}; fields: attempts, breaks, avgScore, recentRunVerdicts; how
     technique selection is weighted; cross-session persistence via IDB
       - Track C: failuresArchive — refusal fingerprints {prompt_head, response_head, ts}; how they inform mutation avoidance
       - Track D: payloadStats — per-category jailbreak effectiveness; probability adjustment logic
       - Export functions: exportLessons(), exportFailureFingerprints(), exportBreakSignatures()
       - renderMemoryBlock() — how all 4 tracks compose the RT's memory context block
     9. Evaluation Engine — AttackEvaluator; 4 outcomes (success/partial/refused_with_leak/failed); 5 scoring dimensions (refusal_quality
     0–3, leakage_class, groundedness 0–3, uplift 0–3, technique_signature_match bool); 7 rubric anchors (scores 0,2,4,6,7,8,10 with
     rationale for each); OWASP-LLM mapping (LLM01–LLM10) on every record; how the judge prompt is assembled
     10. Core LLM Attack Techniques (27) — full catalog table: ID, name, mechanism, key phase behavior, target vulnerability class, OWASP
     mapping. Grouped by mechanism family:
       - Persona/Role techniques: DAN, Persona Adoption, Role Reversal Injection, Persona Drift, Comparative Asymmetry
       - Escalation techniques: Crescendo, Trolley Problem, Priming Cascade, Confidence Erosion
       - Injection techniques: Frame Injection, Indirect Injection, Nested Instruction Smuggling, Context Window Poisoning, Reflective
     Poisoning
       - Social techniques: Emotional Manipulation, Authority Impersonation, Authority Laundering, False Consensus Seeding
       - Cognitive techniques: Many-Shot, Hypothetical Chain, Hallucination Amplification, Semantic Satiation, Mosaic Assembly,
     Comparative Inference
       - Extraction techniques: Token Smuggling, Stereotype Elicitation, Close-to-18+
     11. Attack Categories (11) — table: ID, label, description, why it's a valid red-team target, typical technique pairings
     12. Domain Intent Packs (15 Verticals) — for each: sensitive_assets, high_value_failure_modes, privileged_corpus_signals,
     regulator_authority_pretexts, intent_seeds. Verticals: Tax, Medical, Legal, Finance, HR, Customer Support, Education, Cybersecurity,
     Government, Insurance, Pharmaceutical, Retail, Software Engineering, Consumer Banking, Travel
     13. RAG Attack Techniques (45 across 4 layers) — for each layer: objective, attack surface, then each technique with: name,
     mechanism, what it exploits, expected failure mode, detection hint
       - Layer 1 — Retrieval (11 techniques): keyword hijack, negation-blind, authority spoof, starvation, polluted corpus, homoglyph
     collision, top-K exfil, facet pivot, synonym chain, metadata leak, query-log inversion
       - Layer 2 — Embedding (11): paraphrase drift, neighbor anchor, low-norm cryptic, cross-lingual pivot, decoy collision, adversarial
     suffix, typo decoy, chunk alignment, semantic satiation drift, query inversion, distractor flood
       - Layer 3 — Context Window (11): indirect injection, context-window overflow/eviction, chunk-boundary split, instruction-hierarchy
     inversion, tool-log poisoning, role relabel, quote-envelope escape, persona drift via history, summary-compression gap, citation
     replay, multi-doc contradiction
       - Layer 4 — Integration/Generation (12): citation fabrication, source blending, refusal-vs-retrieval misroute, grounding decay,
     cross-doc synthesis, disclaimer strip, translation laundering, summary amplification, policy-quote dodge, partial-answer completion,
     self-consistency pressure, attribution swap
     14. Filter-Layer Probes (12) — targeting cloud-provider content classifiers independent of the underlying model. Each probe: name,
     methodology, what gap it reveals, expected findings, provider-specific notes:
       - encoding_rotation, threshold_bisection, length_truncation, streaming_leak, response_self_elaboration, category_gap,
     filter_fingerprint, indirect_injection_vs_prompt_shield, multi_turn_abuse_score, config_drift, system_prompt_bypass, multilingual_gap
     15. Surface Probes (OWASP-LLM Aligned) — grouped by OWASP LLM Top 10 category:
       - LLM02 Output Handling (7 Phase A + 4 Phase B): SQL echo injection, NoSQL operator injection, CSV formula injection, markdown
     image exfil, markdown link exfil, stored XSS echo, ANSI escape injection; Phase B: PostgreSQL CTE injection, MongoDB aggregation,
     GraphQL introspection, ORM mass-assignment
       - LLM07/08 Tool Call Security (6 Phase A + 6 Phase B): NL-to-SQL injection, SSRF via web-fetch, path traversal, command injection,
     confused deputy, tool-call loop DoS; Phase B: PG stacked query, Mongo $where, GraphQL alias DoS, batching abuse, Sequelize operator,
     Prisma $queryRaw
       - LLM06/10 Sensitive Information Disclosure (8): system prompt extraction, tool schema disclosure, embedded secret leak,
     cross-tenant data leak, training data extraction, memorized canary probe, verbatim continuation, repeat-sampling consistency
       - LLM04 Resource/DoS (4): token explosion, latency amplification, memory/state bomb, quota exhaustion
     16. Provider Support & Configuration — supported providers (OpenAI, Azure, Anthropic, Google, HuggingFace, Ollama,
     Custom/OpenAI-compat); fields required per provider; streaming vs non-streaming; model pricing table; why HuggingFace is recommended
     as RT provider; Azure endpoint format
     17. Reporting & Exports — session report structure; per-technique breakdown; OWASP mapping in export; JSON export schema;
     calcSessionCost() formula; costHistory for trend tracking; what "Break Rate", "Avg Score", "Partial Rate" mean in context
