Surface Attack Builder

Probe the chatbot's integration surface — output rendering, tool calls, persistent state, resource limits. OWASP-LLM Top 10 aligned: LLM02 / LLM04 / LLM06 / LLM07 / LLM08. McKinsey-class attacks live here.

◌
Application Surface probing is not enabled on the target
To use this builder, go to Configuration → Target and tick Enable Application Surface Probing. Then return here to declare the chatbot's integration surface and pick OWASP-LLM-aligned probes (LLM02 / LLM04 / LLM06 / LLM07 / LLM08).
Target Surface 0 declared

Declare what the chatbot is connected to. Probes whose preconditions don't match will be skipped at session start. Be honest — over-declaring runs probes that can't land; under-declaring hides findings.

Auto-Tune Learning

Cross-session learning from past sessions — successes, failures, and lessons feed silently into future red-team prompts and payload selection.

Status 0 entries

When enabled, five channels persist to localStorage: break seeds (intent re-breeding), per-technique lessons, (technique × category × target) success-rate matrix, failure fingerprints (so refused phrasings are explicitly avoided), and per-payload break rates (Bayesian-smoothed weighting in pickPayload). These flow silently into the red-team system prompt and payload selection on every subsequent session — the tool sharpens with use. Disabled by default; opt-in. Storage is local to this browser.
